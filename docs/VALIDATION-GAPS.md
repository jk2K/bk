## 证据要求

每次验收至少保存：代码或源文件哈希、运行环境、执行命令、断言结果、原始日志、失败项、测试数据性质、模型替身标记、截图/视频和来源 Commit。截图只证明相应可视状态；录屏不是真实模型语义正确性的证明。

## 复跑故障注入

在 Linux 上执行 `node --import tsx scripts/e2e-recovery.ts`。脚本创建临时 Git 仓库、Git TCP 服务和独立 BK 进程，故障注入仅作用于这些进程。默认写入 `.bk/validation/e2e-recovery.json`。可用 `BK_E2E_WATCH_MS` 延长本地 watch 观察窗口。该脚本属于 `npm run validate:artifacts` 的自动检查。模拟的模型和审核服务不能用于关闭其他 P0 验收项。

企业试点执行前，需要明确允许发送给模型的 PRD 变更与人工标注图片，以及可写的 GitHub、GitLab 和 Gitea 测试仓库和有权限的 CLI 会话。内网与 SSO/MFA 由授权测试人员在内网机器执行，记录时间、版本、状态和脱敏证据。凭据只通过目标环境的认证配置提供。
