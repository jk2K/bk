# BK 0.2 剩余工作与验收门槛

当前状态：工程开发预览，可用于受控试点准备；尚不满足完整 V1 验收。自动测试通过不等于真实模型、真实登录和真实平台均已验证。

## 发布前必须验证

| 优先级 | 工作 | 当前证据 | 完成标准 / 还需条件 |
| --- | --- | --- | --- |
| P0 | 企业 Claude 认证和真实业务语义链路 | SDK 权限/Schema/MCP 用真实实现；模型返回使用测试替身 | 在批准的模型环境，以真实 PRD 变更跑完 scan → analyze → proposal；记录模型、输入版本、用量、人工判定和最终 Diff |
| P0 | 图片理解准确率 | 字节 Hash、图结构约束、Mermaid 解析和不确定性处理通过；看图结果为替身 | 用有人工答案的流程/架构/图表/UI 样本验证；保存原图 Hash、结构化结果、视觉核对和人工复核结论 |
| P0 | 企业内网 Git 和 SSO/MFA | 本地 Git、真实 Chromium、持久 Cookie、401 和边界拦截通过 | 在内网电脑用真实授权访问私有仓库及 Wiki，覆盖登录、浏览器/CLI 重启、到期、重新认证；需要测试账号和内网环境 |
| P0 | 三类 Git 平台真实审核闭环 | gh / glab / gt / tea 契约模拟通过 | GitHub/Gitea/GitLab 测试仓库分别实测创建、重跑、关闭、人工编辑、合并和正式分支刷新，保存 URL、Commit 和 CLI 版本 |
| P0 | 真实中断与长时间运行 | SQLite 状态恢复、事务回滚、重试及预算恢复通过 | 对采集/分析/提交分别执行真实进程终止、断网和“远端成功/本地失败”故障注入；至少一个完整日常运行周期，无漏事件/重复发布 |

## 仍需开发的 V1 能力

| 优先级 | 工作 | 当前边界 | 完成标准 |
| --- | --- | --- | --- |
| P1 | 同规则跨事件更新同一 PR | 目前按事件隔离；连续更新同一规则可能产生多分支冲突 | 新变化更新已有待审核提案，保留人工编辑，不覆盖已拒绝结论；覆盖并发和失败恢复 |
| P1 | 跨来源联合分析与审核反馈 | 已有定位反查、关键词和相邻规则；尚无完整 PRD/设计/代码联合证据链 | 引用固定版本的多来源证据，区分批准意图与实现偏差；记录拒绝/人工编辑反馈并抑制无意义重复 |
| P1 | 受限跨页浏览与 Recipe 审核发布 | 当前仅同文档控件；Recipe 在本地回放后需人工纳入 Git | 分页仍受 URL/页数/方法边界限制；Recipe 走独立可审核提案，失效不误判内容删除 |
| P1 | 大 Diff 分块、来源迁移、指标 | 当前超限暂停；改来源身份需新 ID；仅共享单模型并发 | 无遗漏地处理大变更；明确迁移检查点；可查看成本、处理时间、待审率和失败趋势 |
| P1 | doctor 在线探测与稳定错误码 | 当前检查认证环境，不实际试调用模型 | 提供显式的在线探测和可自动化判断的错误分类；不偷偷外发内部资料 |
| P1 | 真实业务评测集 | 42 项工程用例不是业务召回率评估 | 人工标注新增/修改/冲突/噪声/缺证据样本，测召回、采纳率、重复率及审核时间；PRD 中的建议指标尚未证明达成 |
| P2 | 开源/发行准备 | 可构建和打包，尚未正式发布；许可证为 UNLICENSED | 确定许可证和发布权限，版本/变更日志/安装升级/支持平台文档齐全，再发布 npm/Release |

向量检索、多 Agent 并发和专用时序图/ER 渲染可按试点需求增强，不应替代上述真实验收，也不必为了第一批试点引入额外在线知识服务。

## 证据要求

每次验收至少保存：代码或源文件哈希、运行环境、执行命令、断言结果、原始日志、失败项、测试数据性质、模型替身标记、截图/视频和来源 Commit。截图只证明相应可视状态；录屏不是真实模型语义正确性的证明。
