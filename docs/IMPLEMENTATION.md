## 当前安全与恢复边界

- 单机进程锁与 SQLite 事务保证同一知识库写流水线串行；未使用跨主机协调锁。
- 源快照完整持久化后才推进扫描游标；分析失败不覆盖待办；移除来源会暂停已有待办。
- 同 ID 来源身份/范围变动会要求新 ID；无效热加载保留上一有效配置。
- 未知生效状态、证据不足、重写历史、源码/测试独立变化生成待确认或冲突报告。
- 扫描不全量忽略空白差异，因为缩进与字符串中的空格可能改变业务行为；纯格式变化由模型判断 no_change。
- 规则文件必须有 YAML 元信息和受管理正文标记；不自动改造未知人工文档格式。
- 图片、复杂浏览和限制以上的大变更不会被静默标记为“已理解”。
- 模型抽取与真实业务判断仍需要人工审核；真实性校验只证明引用存在，不证明模型解释必然正确。
- SQLite 与快照可重建，但已消失、未入 Git 的历史网页无法保证恢复。
- CLI 远程操作参数根据平台适配；真实 CLI 版本差异会报错并保留重试事件，不进行自动合并。

## 验证方式

自动测试覆盖配置约束、输出符号链接、进程锁、SQLite 回滚与中断恢复、真实 Git 增量/强推、原文证据校验、业务意图冲突降级、干运行、失败重试和隔离提案。Provider 测试模拟三类平台及旧版 tea 的正常与重复创建流程。Mermaid 使用实际解析器测试合法与非法示例。

完整验收还需要用户环境中的浏览器、企业批准的 Claude 模型及 Gitea/GitHub/GitLab CLI 登录；本次不宣称这些在线链路已经实测通过。
